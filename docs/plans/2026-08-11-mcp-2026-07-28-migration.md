# MCP 2026-07-28 Migration Implementation Plan

## Objective

Migrate BliSolver's stdio MCP server from Python SDK 1.x `FastMCP` to the stable Python SDK 2.x
`MCPServer`. The resulting server must serve modern MCP `2026-07-28` and retain SDK-provided
compatibility with legacy MCP `2025-11-25` clients.

## Architecture boundary

- Keep the Agent Plugin stdio transport, `mcp.json`, and `bin/blisolver-mcp` launcher contract.
- Replace the high-level SDK server entry point; keep the five tool names, parameters, payloads,
  and job-store semantics stable.
- Modern clients use MCP `2026-07-28` self-describing requests and may discover capabilities with
  `server/discover`; legacy clients continue to use `initialize` and MCP `2025-11-25` through SDK
  compatibility.
- Do not add `stateless_http`. It configures Streamable HTTP and is not needed for stdio or to
  enable MCP `2026-07-28`.
- Treat `job_id` and `${PLUGIN_DATA}` records as explicit application state. They must not depend
  on an MCP protocol session.
- Do not call roots, sampling, or MCP protocol logging; introduce MRTR/`input_required` flows; or
  enable/declare the Tasks extension. BliSolver's existing job API is not an MCP Task.
- Do not run live ingest, download media, use credentials, or invoke external models during this
  migration.

## Change set

### 1. Lock the target behavior in tests

Modify `tests/test_packaging.py` and add `tests/test_mcp_protocol.py`.

- Require `mcp>=2,<3`; reject SDK 1.x and 3.x.
- Build the server with the installed SDK v2 API.
- Exercise modern in-memory negotiation and assert protocol version `2026-07-28`.
- Exercise legacy negotiation and assert protocol version `2025-11-25`.
- Assert that the modern `tools/list` result carries the `ttlMs` and `cacheScope` cache hints
  required by the new protocol revision.
- Call the pure local `get_transcript` unknown-job path in both modern and legacy modes.
- Assert the exact tool order, not a set comparison:

  1. `probe_video`
  2. `extract_transcript`
  3. `get_transcript`
  4. `get_timeline`
  5. `get_visual_context`

- Add a real stdio end-to-end test that starts `bin/blisolver-mcp` through the official v2 client
  with bounded read and overall timeouts, performs modern discovery, lists tools, checks the exact
  order above, and terminates cleanly. The test must use a controlled temporary `${PLUGIN_DATA}`
  and must not invoke any media tool.
- Keep a legacy protocol test against the same server implementation.

Run the focused tests before the production change and confirm that the current SDK 1.x
implementation fails for the expected dependency/API reasons.

### 2. Migrate the server implementation

Modify `pyproject.toml`, `blisolver/mcp/server.py`, and `blisolver/mcp/__init__.py`.

- Change the optional dependency to `mcp>=2.0,<3`.
- Replace `mcp.server.fastmcp.FastMCP` with `mcp.server.MCPServer`.
- Construct the server with BliSolver's own `__version__`.
- Preserve all five tool registrations and their current payload helpers.
- Preserve stdout as JSON-RPC only and stderr for diagnostics.
- Do not introduce protocol-session state or change the persisted job store.

Run the focused packaging and protocol tests. Both protocol versions and the real stdio path must
pass before continuing.

### 3. Align current documentation

Update `AGENTS.md`, `README.md`, and
`skills/blisolver-video-ingestion/references/mcp-contract.md`.

Document:

- SDK v2 `MCPServer`;
- modern `2026-07-28` plus legacy `2025-11-25` compatibility;
- why stdio does not use `stateless_http`;
- why explicit `job_id` plus `${PLUGIN_DATA}` is application state rather than MCP session state;
- that this server does not call roots, sampling, or MCP protocol logging; introduce
  MRTR/`input_required` flows; or enable/declare Tasks.

Run the skill and package contract tests after the documentation changes.
